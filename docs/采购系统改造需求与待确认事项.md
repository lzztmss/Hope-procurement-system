# 海魄采购系统改造需求与待确认事项

> 当前阶段：需求梳理，尚未开始功能开发。  
> 原则：只修改“采购系统测试版”，不修改公网生产版；所有功能先在本地独立数据库中测试。

## 一、改造目标

目前各模块更像互相独立的登记表。此次改造的核心是让业务数据沿着同一条业务链流转，避免重复填写，并确保不同岗位在权限允许的范围内看到同一份实时数据。

建议的主流程：

`线索 → 销售订单 → 库存检查 → 出库 → 培训验收 → 售后`

库存不足时增加采购支线：

`销售订单库存不足 → 提醒有采购权限的人员 → 审批通过 → 生成采购任务/采购单 → 到货入库 → 回到销售订单出库`

售后换货时增加返向出库：

`售后订单确认需要换货 → 生成换货出库单 → 扣减库存 → 记录换货结果`

## 二、已确认需求

### 1. 线索与销售订单

- 在线索模块下增加“销售订单”模块。
- 可以从一条线索一键生成销售订单草稿，自动带入已有客户和负责人等信息。
- 一条线索可以生成多张销售订单。
- 销售订单不能自动直接出库：员工核对订单后提交审批，审批通过后才允许检查库存、发起采购或生成出库单。
- 当前测试版暂定系统管理员、公司领导、业务统筹可以审批销售订单；正式岗位确定后改为可配置权限。
- 销售订单拟包含：
  - 客户
  - 产品、型号、数量、单价、总价
  - 合同编号、合同附件
  - 预计交付日期
  - 负责人
  - 订单状态
  - 开票信息
  - 回款信息
- 产品必须从现有产品档案的下拉菜单选择，避免自由输入造成同一产品出现多种写法。

### 2. 销售订单与库存、采购的联动

- 销售订单提交后，系统自动检查可用库存。
- 库存充足时，可以继续生成出库单，订单中的客户、产品、型号和数量自动带入。
- 库存不足时，不直接采购：
  1. 系统生成缺货提醒；
  2. 所有拥有采购审批权限的人员可以看到提醒；
  3. 其中一人审批通过后，才允许生成采购任务或采购单；
  4. 采购到货并入库后，更新库存，再继续出库。
- 采购过程需要与销售订单、库存和出库关联，不能只是单独登记一条采购记录。
- 具体由哪些职位审批、是否需要多级审批，暂未确定。

### 3. 库存新增与合并

- 产品字典以“产品名称 + 设备型号/规格”维护；同一名称可新增多个型号，每个名称与型号组合对应一个产品 ID。
- 采购、销售、线索、库存、培训和售后均先选择产品名称，再从该名称已有型号中选择；型号为必填，不允许自由手写。
- 同一个“产品名称 + 型号”再次入库时，直接增加原库存数量，不新增重复库存行；不同型号必须分别建库存记录。
- 页面可以按产品名称汇总显示各型号总量，但采购、出库、换货和库存检查必须按具体型号计算，不能用其他型号的库存凑数。
- 系统内部应使用稳定的“产品 ID / SKU”判断是不是同一个产品，不只比较显示出来的名称。
- 每次库存增加或扣减都应保留库存变动记录，至少记录：
  - 产品
  - 增减数量
  - 变动前数量
  - 变动后数量
  - 来源单据
  - 操作人
  - 操作时间
- 暂时不记录单台设备串号。

说明：SKU 可以理解为商品的“库存货号”。例如“AI 健康手表 4G 养老版”在系统内部有一个固定编号。员工仍然从下拉菜单选产品，不需要自己填写 SKU；系统用这个编号可靠地合并库存。

### 4. 出库

- 出库单优先由销售订单生成，不再重复填写客户、产品、型号和数量。
- 出库完成后自动扣减对应产品库存。
- 出库记录必须保留来源销售订单，方便追溯。
- 现阶段暂不要求逐台填写串号。

### 5. 培训验收

- 在“出库”和“售后订单”之间增加“培训验收”模块。
- 增加技术/培训相关权限，供负责客户培训和验收的员工使用。
- 培训验收单建议从出库单生成，并自动带入客户、产品和项目资料。
- 建议字段：
  - 客户
  - 关联销售订单、出库单
  - 培训日期、地点
  - 培训人员、客户参与人员
  - 培训内容
  - 验收结果
  - 客户签字或验收附件
  - 问题记录
  - 处理状态

### 6. 售后换货与库存

- 售后订单确认需要换货时，可以一键生成换货出库单。
- 自动带入客户、产品、型号、数量和原售后单编号。
- 换货出库完成后自动扣减库存。
- 暂时不跟踪设备串号。
- 故障旧设备是否进入“不良品库存”、返厂或报废，仍需确认。

### 7. 权限

- 采用“职位默认权限 + 员工个人例外权限”。
- 功能操作建议使用多选，可分别勾选：
  - 查看
  - 新增
  - 编辑
  - 删除
  - 导出
  - 审批
- 数据范围不建议把“全部、本部门、仅本人”同时多选，因为它们会互相包含；这里保留单选。
- 如果需要精确授权，再增加多选项：
  - 指定部门（可多选）
  - 指定员工（可多选）
- 所有模块应从同一份数据库读取数据。职位不同只决定“能看什么、能做什么”，不应生成各自独立的数据副本。

## 三、已发现的 Emily 库存显示问题

当前测试数据中：

- Emily 属于采购部，职位为采购，数据范围是“本部门”。
- 四条库存记录的负责人都是仓库员工。
- 现有程序会按照记录负责人所属部门过滤“本部门”数据。

因此 Emily 可能看不到仓库部负责的库存，或看到的数量与拥有“全部”权限的管理员不同。这不是库存真的消失，而是库存模块错误地沿用了普通业务记录的部门过滤规则。

建议：库存“数量”是公司的统一事实，拥有库存查看权限的人应看到同一库存总量；是否能新增、修改、盘点、出库，再由操作权限控制。若有仓库隔离需求，应按“仓库/库位”授权，而不是按库存记录负责人所属部门过滤。

## 四、暂缓处理

- 设备串号的逐台追踪。
- Excel 批量导入串号及导入模板。
- 第 12 项原问题，暂不处理。
- 多人实时同步：正式上线前需增加实时推送或安全的自动同步机制。其他账号新增、审批、到货、出库、作废后，应自动更新相关人员的待办与铃铛动态；用户正在填写表单时不得自动覆盖其内容。
- 左侧待处理数字：在销售订单、采购需求、出库交付、培训验收、售后工单等菜单显示当前账号“可处理”的数量。数量须同时按数据范围、模块操作权限和流程按钮权限计算；无权限或数量为 0 时不显示。待实时同步完成后，再让其他账号的待办数字自动更新。
- 上线前权限验收：核心流程和售后流程全部稳定后，将本次新增的流程按钮逐项加入员工权限配置并核对默认岗位权限。例如销售提交/审批/库存检查、采购技术确认/审批/到货、出库/签收/验收、培训验收、售后退库收货/质检入库/维修/报废/换货出库。管理员保留全部权限；普通员工只显示并可操作其被授权的按钮。

## 五、尚待确认的问题

1. 哪些职位可以审批缺货采购？一人通过即可，还是需要多级审批？
2. 采购单需要哪些状态，例如待审批、已审批、采购中、部分到货、已完成、已驳回？
3. 销售订单正式使用哪些状态，以及取消订单后是否自动释放已占用库存？
4. 库存“可用数量”是否按“现有库存 - 已锁定数量”计算？
   - 这里的“已锁定库存”建议定义为：已经被已审批销售订单预留、暂时不能再分配给其他订单的正常货物；它不是坏设备，也仍然在仓库中。
   - 请确认：订单在哪一步开始锁定库存（销售审批后、库存检查通过后，还是生成出库单后）？订单取消、作废或回撤时，是否自动释放锁定数量？
5. 是否允许一张销售订单分多次出库、采购单分多次到货？
6. 售后换下来的故障设备如何处理：不良品库存、返厂、维修后重新入库，还是报废？
   - 建议原则：换货退回的故障设备不能直接加回“正常可用库存”。只有质检合格，或维修完成并复检合格后，才能重新进入正常库存；确认报废的设备不增加正常库存。
   - 请确认：是否需要独立记录“不良品/待维修库存”？若需要，是否还要区分“待质检、维修中、待返厂、已报废”几种数量，以及分别由谁操作？
7. 培训验收未通过时，是退回重新培训，还是可以直接建立售后订单？
8. Emily 的实际异常需要补充复现信息：她使用的账号、进入的具体页面、看到了哪一条库存、什么时候消失，以及管理员同一时间看到的内容。
9. 历史重复库存如何清理和合并，合并前是否需要公司人员确认。
10. 后续串号表格有哪些列、是否需要校验重复串号、错误数据如何提示。
11. 每种单据分别哪些字段必须填写：确认后，系统在用户点击确认/保存时，对未填写的必填项进行红色标记和提示；现阶段先不自行假设必填规则。
12. 日期预警规则：临近截止日期的日期要标红提醒；需确认哪些单据使用此提醒，以及提前几天开始标红。
13. 正式测试环境前统一编号规则：当前本地版使用“前缀 + 时间数字”临时防重，不能作为正式业务编号。建议销售订单、采购单、出库单、培训验收单、售后工单、线索分别采用“单据前缀 + 日期 + 当日流水号”，例如 `SO-20260729-0001`；产品编码采用固定前缀 + 类别 + 流水号，例如 `PRD-WATCH-0001`。请确认是否有公司现成编号规范、是否需要按部门/项目区分编号。

## 六、建议开发顺序

1. 先统一权限和库存可见性，补库存变动记录。
2. 增加销售订单，并打通线索 → 销售订单。
3. 打通销售订单 → 库存检查 → 缺货提醒/采购审批。
4. 打通采购到货 → 入库，以及销售订单 → 出库 → 扣减库存。
5. 增加培训验收。
6. 增加售后换货 → 换货出库。
7. 最后增加串号管理和 Excel 批量导入。

## 七、验收基本原则

- 同一时刻，不同账号在权限允许的情况下看到相同的库存数量。
- 每次库存变化都能查到来源、操作人和时间。
- 从前一步生成后一步时，已有资料自动带入，不重复录入。
- 每张采购、出库、培训验收和售后单都能追溯到原销售订单及线索。
- 权限同时控制“能否看到”和“能否操作”，且管理员可以清楚配置。
